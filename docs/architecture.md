# 完整执行链条与功能位置

本项目是本地模拟客服原型。共同主线是：接收需求 → 校验身份 → 调用工具取证 → 结果回填 → 主客服回答 → 保存过程与可选进度 → 后续继续。

## 主循环

1. `app.py` 检查业务存储，按开关装配模型、知识库和可选组件。
2. `LiveSession` 绑定程序认可的客户身份并创建 `Harness`。普通 live 从访客开始；登录或退出会建立全新上下文。
3. 自然输入触发 `UserPromptSubmit`，整理可交付的后台 / 队友结果和上下文预算；按需召回本人记忆。
4. DeepSeek 接收 system、messages 和工具目录，决定直接回答还是请求工具。
5. 程序执行 `PreToolUse`、参数 / 身份 / 归属 / 范围检查，再分发实际调用。
6. 每个调用产生与原 `tool_use_id` 配对的 `tool_result`，执行 `PostToolUse`；完整批次回填并保存后，再进入模型请求。
7. 主客服生成最终文本，保存消息并执行 `Stop`；成功时按开关提取和校验长期记忆，再显示回答与实际保存状态。

默认主循环最多 8 个逻辑 step；超限会保留记录并标记未完成。终端打印不替代工具结果回填。主执行器对同批普通工具调用同步依次处理；子任务不自动并行。

## 所有能力在链条中的位置

| 功能 | 触发位置与作用 | 如何回到主链 / 边界 |
| --- | --- | --- |
| Agent Loop / Tool Calling | 主模型提出下一步工具请求 | 程序执行，结果回填，主模型继续 |
| 本地身份与授权 | 建立会话、每次私人查询前 | 程序绑定身份；SQL 限制订单归属；用户自称或模型参数不能切换身份 |
| Hooks | 输入、工具前后、回合结束 | 记录成功、失败、拒绝；可信回调不能授予权限 |
| Todo | 模型拆分当前复杂需求时 | `todo_write` 的完整清单投影给后续模型；清单完成不证明业务解决 |
| 一次性子 Agent | 主模型调用 `task` | 独立上下文调查，有限报告与真实证据作为父工具结果返回 |
| Skill | 模型按需调用 `load_skill` | 指南正文进入结果，之后仍要查询业务事实；指南不是政策或授权 |
| 上下文管理 | 每个模型 step 之前及显式 / 异常分支 | 配对校验、结果预算、snip、条件 micro/fit、显式允许的摘要 |
| 受控原文查回 | 需要已归档的原始诉求 / 工具正文时 | 通过本客户本会话登记 ID 查回；无任意路径读取 |
| SQLite 业务工具 | 商品、订单、本人订单列表查询 | 结构化事实带来源回填；分单位整数转金额 |
| JSON 政策 / 物流 | 明确政策目录或订单物流查询 | 物流先检查订单归属；最新记录不等于实时位置 |
| RAG | 公开政策、FAQ、商品说明提问 | 查询向量 → 有效公开片段 → 相邻原文 → 引用证据回填 |
| 长期记忆读取 | 本轮首次主模型请求前 | 仅本人且已开启；作为背景，不替代实时订单事实 |
| 长期记忆保存 | 回答保存、Stop 成功后 | 程序核对候选与客户原句、类型、长期性及身份；附保存回执 |
| 持久调查任务 | 客户需要跨会话调查时 | 保存任务 ID、依赖、状态和 note；下次读取后重新核查必要事实 |
| 后台物流 | 已开启，且可与其他工作重叠时 | 先回提交状态，后由已有循环收取结果；保存后 ACK |
| 每日查询安排 | 客户希望未来每天查物流时 | 身份匹配且 CLI 存活时触发；结果在下一次终端输入时显示 |
| 持续队友 | 已开启的物流 / 政策调查 | 小步骤卡 → 独立工具核查 → 有限报告 / 证据 → 父消息保存 → ACK |
| 日志、用量、预算 | 横穿整个执行过程 | 保存执行证据和未完成状态；缺失 usage 不当作 0 |

所有分支按需求和开关触发，不需要一次咨询同时经过全部功能。

## Agent、Skill 与上下文隔离

主 Agent 的职责是理解用户需求、选择受控工具、判断是否继续取证，并组织最终答案。工具目录、固定角色、调用预算和程序权限共同限定可执行路径；这里没有单独实现一个全局智能路由服务。

Skill 是按需加载的操作指南。启动时仅暴露名称和简介，模型获取正文后再按步骤查事实。Skill 自身不创建独立模型上下文，也不直接代表工具已执行。

一次性 s06 子 Agent：

- 只接收本次明确任务、受限工具与自己的消息历史，不复制父完整对话。
- 同步、一次性，无递归；每父回合至多一次委派，子循环最多 3 步。
- 没有 RAG、长期记忆、持久任务、后台或团队工具。
- 返回有长度限制的报告及实际工具证据；父客服继续作答，无自动重试。

持续 s13 队友：

- 物流 / 政策角色拥有各自有限工具和独立上下文，同父会话可复用。
- 通过显式任务、步骤卡和报告交接通信；父保存后才 ACK。
- 重新登录、退出或会话关闭会隔离旧队友；迟到结果不能当作新身份结果。
- worker 不继承主客服 RAG、记忆和持久任务工具；同父回合的团队委派与 s06 委派互斥。
- 真实受控试验验证过程序固定分工和上下文复用；自主组队尚未形成普适验证。

报告和工具正文都是待核查资料，不能改变用户授权、当前身份或程序权限。

## 四种“任务”分别保存什么

| 名称 | 生命周期 | 作用 |
| --- | --- | --- |
| `todo_write` | 当前主会话 | 当前需求步骤清单 |
| `task` | 单次子调查 | 调用一次性子 Agent |
| `create_task` 等 | 按客户跨会话保存 | 调查依赖、进度与 note |
| `start_team_task` 等 | 同父会话 | 队友执行的小步骤卡与交接状态 |

后台查询是进程内作业；每日安排是持久触发定义。它们不会自动把持久调查标为完成。重启不会自动还原旧 Harness 消息或原队友，历史消息文件主要是运行证据。

持久记忆支持 user / feedback / project / reference 四类。普通当前要求、模型推测、工具原文和敏感凭据不能直接变成客户长期偏好。下次登录读取记忆或任务后，需要按当前需求重新查询可能变化的业务事实。

## 上下文、失败和恢复

正常请求前按条件执行：工具配对校验 → 最新批次长结果预算 → snip 归档 → micro → fit → 允许时自动摘要。字符估计不等于精确 token，摘要也不保证信息零损失。

模型主动请求 compact 时，等待完整批次工具结果回填后处理。自动摘要、主动摘要与已识别上下文溢出的 reactive 恢复，每用户输入共用至多一次摘要尝试。

仅在明确上下文超长且允许摘要、还有额度时，重试失败的主模型请求一次。已经成功执行的工具不重做。普通 API 错误、子 Agent 失败不会套用该恢复；没有通用自动重试或分布式事务回滚。

权限拒绝、工具失败、空结果分别保留实际状态，不能伪装成成功。队友失败卡可显式继续，迟到结果失效；预算、审计或消息保存失败可停止本轮并保留未完成信息。调查 note 是后续接续线索，不等于所有执行状态能自动跨进程恢复。

## 一条已手动跑通的业务链

登录 Alice → 自然询问 A1001 实付和清洗方法 → 主模型选择 `get_order` + `search_knowledge` → 程序取出历史 16900 分和清洗原文 → 工具结果回填 → 按需 `get_product(P100)` 查现价 19900 分 → 主客服分开回答金额与使用说明 → 保存消息和审计 → 等待后续输入。

该案例用真实 DeepSeek 完成；业务数据为合成。其他可选开关当时未开启，不计为该次已执行步骤。历史回答出现过金额差异原因的措辞问题，共享金额规则已修正，修正后的新真实生成仍待手动复测。
