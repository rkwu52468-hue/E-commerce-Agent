# 中文向量 RAG：从原文到回答

## 数据与索引

知识原文位于 [documents.json](../data/knowledge_demo/documents.json)，全部为本项目人工 / AI 辅助构造的课程模拟资料，并非互联网检索到的真实商家文件。27 条原始记录中，当前有 22 篇本店有效公开资料，构成 66 个片段；其他记录用于范围和有效期过滤测试。

构建链条：

1. 校验记录、店铺范围、访问范围、版本和有效期，选择有效公开资料。
2. 按标题 / 段落拆分，保留原文、文档 ID、片段 ID、source、version 和 content_hash。
3. 用 FastEmbed 的 `BAAI/bge-small-zh-v1.5` 生成真实 512 维中文向量，并检查实际 tokenizer 长度。
4. 写入新的 Qdrant Local 代际索引，保存 manifest 与哈希，再切换 CURRENT。

模型文件、向量索引和运行报告由本机生成，不在 Git 仓库中。索引与原文 / 模型指纹不匹配时拒绝继续使用并要求重建；原资料删除、变更或新版本开始有效时需要重建。已过期片段在查询时过滤。

## 在线检索怎样进入主模型

`--live --allow-knowledge` 向主客服提供 `search_knowledge`。模型可根据自然语言自行选择它，不要求客户写工具名。

查询向量 → 按本店 / 公开 / 有效范围过滤 → 至多 3 个 dense hits（cosine ≥ 0.5）→ 补同文档相邻片段 → 裁剪合并证据 → 返回 tool_result → 主模型读取并生成答案。

输出区分：

| 字段 | 含义 |
| --- | --- |
| `hits` | 真正参与向量排名的主命中，带相似度 |
| `context` | 同文档、同版本、同来源的有效相邻原文，最多 3 段，`score=null` |
| `chunk_id` / `doc_id` | 追溯具体片段和文档 |
| `source` / `version` | 原文来源标识及资料版本 |
| `content_hash` | 核对正文与索引一致性 |
| `context_policy` | 说明相邻补充规则 |

`canonical(hits + context)` 的 JSON 长度最多 3000 字符，外层工具元数据不在此限额中。这不是模型输入的总 token 上限，也不保证每次返回 6 段。

相似度代表相关程度，不能当正确率或资料适用性的证明。真实故障与“查询成功但无命中”分别返回状态。

## 为什么补充相邻原文

第一次真实测试问“钢丝球能否刷、应该如何洗”，向量前 3 段包含了禁忌和晾干，但“温水 + 少量中性洗涤剂 + 柔软杯刷 + 充分冲净”位于同一文档另一片段，没有进入主命中。

优化在保留原排名的基础上，受限地补充同文档一跳相邻原文，解决操作步骤被分块截断的问题：

- 补段必须与主命中同文档、同版本、同来源并在有效公开范围内。
- 去重后使用自己的原始 chunk_id，不能沿用主命中的 ID。
- `score=null` 明确标为上下文，不伪装成独立向量命中。
- 主段和补段共享证据字符预算，避免无界扩大上下文。

真实 DeepSeek 复测已经引用补回的正向清洗方法。该优化提高的是证据送达覆盖，同时也带来更多片段与字符，不表示相同 top-k 下免费提升。

目前未加入混合检索或 reranker。当前小语料上的向量结果不保证优于词法基线；详见[评测说明](verification.md)。

## 回答时的证据边界

- 回答依据实际返回的正文，而不是只看标题、source 或相似度。
- 将主命中和相邻补段分别标识，不编造不存在的 chunk_id。
- 清洗方法可概括，但不能从未提供的资料延伸出高温消毒、洗碗机认证等承诺。
- 退货政策仅说明可提交申请、具体审核条件时，不能保证一定退货成功。
- 假设“收到后拆封”不代表订单已经收货。
- 物流没有赔付规则时，不能给出赔付金额；非空检索结果也可能仍存在资料缺口。
- 模型最终引用和语义支持目前主要人工检查，不宣称已做自动逐句验证。

## 结构化订单与 RAG 的协作

私人订单通过登录身份和业务工具查询，不进入公共向量索引。一个查询同时问“我的 A1001 付了多少钱”和“杯子怎么洗”时：

1. `get_order` 在 SQLite 中按当前客户 + 订单号查实际历史成交。
2. `search_knowledge` 查公开使用说明。
3. 必要时 `get_product` 确认商品和当前属性。
4. 主模型分别组织订单事实与知识依据。

169 元历史实付与 199 元现价是两个字段。工具未提供优惠 / 折扣 / 运费明细时，不能从差额推断成因。公共知识说明也不能替代私人订单状态。

## 复现

```powershell
python -m pip install -r requirements-rag.txt
python -m customer_service.knowledge_cli build
python -m customer_service.knowledge_cli search "杯子能用钢丝球洗吗？应当怎么清洗？"
python -m customer_service.knowledge_cli evaluate
python tools/evaluate_knowledge_context.py
```

首次模型下载需要网络；已有缓存后可本地构建、检索和评测。不会调用聊天 API。修改语料后先重建索引；冻结片段评测会核对语料和证据哈希，资料变化时应同步重建合法标注，不能直接沿用旧结果。

启动真实回答：`python app.py --live --allow-knowledge`。只有主客服获得 RAG 工具，当前 s06 子 Agent 和 s13 worker 不继承该能力。
